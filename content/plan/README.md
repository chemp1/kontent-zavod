# plan — контент-план

Календарь публикаций студии: что и когда выходит на каждой площадке.
Показывается на `/studio/plan`, редактируется там же или руками в этих файлах.

## Раскладка

```
rhythm.md                       # сетка ритма: сколько и когда постим на каждой площадке
slots/<дата>-<площадка>[-N].md  # конкретный слот в календаре
```

## Слот

```yaml
---
date: "2026-09-01"
time: "09:00"
platform: threads
rubric: teza                          # ключ из rhythm.md, необязательно
idea: 2026-08-23-tred-lavka-statya    # id папки в ../ideas/, необязательно
material: threads                     # имя файла в drafts/, по умолчанию = platform
---
Заметка: о чём этот слот, пока идея не выбрана.
```

## Состояние слота нигде не хранится

Оно **выводится** из привязанной идеи, и это главное правило раздела:

| Что нашли у идеи | Слот показывает |
|---|---|
| ничего не привязано | пусто |
| идея есть, файла площадки нет | нужен драфт |
| `drafts/<площадка>.md` | черновик |
| `published/<площадка>.md` | опубликовано (со ссылкой) |

Второго статуса в файле слота нет намеренно: он разъехался бы с реальностью
на первой же публикации — ровно так же, как разъезжаются файлы и база.

## Ритм

`rhythm.md` описывает не план, а привычку: «на Threads три поста в день, утром —
тезис». Календарь рисует по нему бледные «призрачные» слоты там, где ритм есть,
а слота ещё не завели, и считает наверху «12 из 21». Чтобы изменить нагрузку —
правится этот файл, а не каждый слот руками.

## Границы

Студия ничего не публикует: календарь про «когда», кнопку жмёт автор
(граница №2 в [`../../CLAUDE.md`](../../CLAUDE.md)).
