# Метод: от текстового файла до контент-завода

Коротко: голос автора - это файл, а не промпт. Правила выводятся из посчитанного корпуса,
а не из представлений о хорошем тексте. Скиллы превращают файл в работу. Сборщики приносят
вход. Публикует человек.

## 1. Голос - это файл

Основа - методология «I am just a text file»: один длинный текстовый файл о человеке.
Мировоззрение, для кого пишет, как звучит, чего не делает никогда, красные флаги.
Не «стиль», а описание автора, из которого стиль следует.

Файл ничего не производит. Он описывает. Всё остальное в этом репо - то, что выросло
вокруг файла, чтобы он работал каждый день.

Структура канона - в `voice/_templates/i_am_just_a_text_file.md`. Пример - `voice/i_am_just_a_text_file.md`
(вымышленный автор).

## 2. Правило без замера - не правило

Регистр площадки - это не «как принято писать на Хабре», а что отличает верхнюю четверть
от остальных в собранном корпусе этой площадки. Отчёты в `content/reports/` - примеры
таких замеров: тысячи статей, медианы, разрывы.

То же с голосом автора. `calibrate.py` считает по корпусу постов, как часто у автора
встречается каждый маркер: длинные тире, скобки-улыбки, хеджи, первое лицо, ритм
предложений, длина. И выводит пороги. Линтер сравнивает черновик не с идеалом, а с автором.

Отсюда правило, которое бережёт от главной ошибки: **инструмент калибруется по автору, а не
по идеалу**. Если линтер забраковал живой текст автора - неверен порог, а не текст.

Иерархия при расхождениях: прямое слово автора → корпус → канон → отпечаток → регистры.

## 3. Скиллы превращают файл в работу

Скилл - папка с markdown, которую модель открывает сама, когда задача подходит.
Никакого сервиса вокруг.

- **Автор** (`write-as-author`): режимы (черновик, редактура, адаптация, синтез, критика),
  регистры площадок поверх канона, блокирующий фактчек имён из транскрибации, критик-луп
  с порогом и лимитом версий, финальный анти-фильтр инфобизнесовых приёмов.
- **Корректор** (`corrector`): линтер механики + три вопроса, которые линтер не умеет:
  тест гороскопа (мог бы это написать кто угодно?), кухня процесса (это суть или отчёт
  о работе?), правило светофора (править только помеченное).

Механика - половина дела. Смысловой слоп линтер не видит: текст может быть безупречен
механически и пуст по сути.

## 4. Вход: сборщики

- **Тренды** (`tools/trend-watch`): раз в сутки обходит фиды, отбирает свежее и пишет
  карточку: суть, почему это касается автора, два-три угла под площадки.
- **Идеи из звонков** (`tools/voice-mine`): из расшифровок встреч берёт только реплики
  автора и ищет мысли, годные для поста. Три слоя приватности: фильтр по спикеру,
  запрет в промпте, редактор цитат с чужими именами.
- **Замеры площадок** (`tools/platform-lab`, `tools/threads-lab`): что залетает и почему,
  чтобы регистры стояли на числах.

Принцип, который держит качество: **робот не пишет постов**. Угол - приглашение подумать;
готовый пост из новости, которую никто не прожил, - конвейер слопа с человеческим лицом.

## 5. Студия

Интерфейс к тем же файлам. Решения принимаются не в терминале: что выходит завтра, какой
тренд взять в идею, какое правило подтвердить. Источник правды - файлы, история версий -
git, базы нет намеренно.

Студия ничего не публикует. Она хранит текст, ссылку и статус. Кнопку жмёт человек.

## 6. Три честных шва

Из первого месяца работы конвейера:

1. Замер чужого сделать легко, замер своего - нет. Пока метрики своих публикаций не
   собираются, регистр площадки описывает чужой успех.
2. Автоматика молчит, когда ломается. Сборщик, который принёс ноль, должен быть событием,
   а не строчкой в логе.
3. Узкое место переезжает в человека. Завод, который производит больше, чем владелец
   успевает прочитать, копит долг, а не ускоряет.
