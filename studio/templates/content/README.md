# content — данные студии

Всё, что накапливает контентная студия. Приложение живёт в [`../studio/`](../studio/),
данные — здесь. Разделены нарочно: приложение можно переписать, данные останутся.

Формат — markdown с frontmatter, потому что источник правды в этой мастерской —
файлы, а не база. Их читает и студия, и сессия Claude Code; будь тут Postgres,
эти два взгляда разошлись бы на первой же неделе.

История версий берётся из git, своей таблицы версий нет.

## Раскладка

```
studio.json            # настройки студии: заголовок, автор, что можно коммитить
ideas/<ГГГГ-ММ-ДД-слаг>/
  idea.md              # заголовок, статус, дата, источник, теги
  source.md            # исходный рамблинг или транскрипт — не редактируется
  thread.jsonl         # история обсуждения вокруг идеи
  drafts/master.md     # мастер-версия
  drafts/telegram.md   # адаптации; в frontmatter — from: drafts/master.md
  published/telegram.md # финальный текст с url и датой публикации
plan/rhythm.md         # контент-план: сетка ритма по площадкам
plan/slots/<дата>-<площадка>.md   # слот календаря; состояние выводится из идеи
plan/candidates/<слаг>.md         # идеи из своих звонков, ждут «принять» или «отклонить»
trends/sources.md      # какие фиды обходит сборщик трендов
trends/<дата>-<слаг>.md # карточка тренда: суть, ссылка, углы
memory/                # уровни памяти + proposals/ на подтверждение
reports/<ГГГГ-ММ-ДД-слаг>.md        # отчёт: title, date, summary, tags + текст
reports/<ГГГГ-ММ-ДД-слаг>.data.json # необязательно: числа для графиков
telegram/rules/        # правила работы с личным Telegram
telegram/projects/     # темы наблюдения за чатами
skill-map.json         # манифест карты скилла
```

## studio.json

Настройки студии, а не контент: как подписывать автора в превью, что показывать
в заголовке вкладки и какие папки студии разрешено коммитить.

```json
{
  "version": 1,
  "title": "Контентная студия",
  "author": { "name": "Автор", "handle": "author", "initial": "А" },
  "git": { "committable": ["content/"] },
  "data": {
    "telegramDigests": ".data/telegram/digests",
    "projectFindings": ".data/telegram/projects"
  }
}
```

`author.handle` — ник в превью площадок, `author.initial` — буква на аватаре.
`git.committable` — префиксы путей от корня; `content/` в списке всегда, остальное
(например, папка скилла) добавляется по желанию. `data.*` — папки вне git, куда
внешние сборщики кладут сводки по Telegram и находки по проектам; студия их только
читает. Файл необязателен: без него студия работает с этими же дефолтами.
`npm run init` в `studio/` создаст его.

## skill-map.json

Карта скилла голоса: какие файлы его составляют и кто что читает. Структура
правится руками, студия из интерфейса меняет только тело файлов и сверяет
манифест с диском на каждый запрос. Без файла раздел показывает пустое
состояние, с битым JSON — текст ошибки; ни то, ни другое приложение не роняет.

```json
{
  "version": 2,
  "note": "…",
  "canvas": { "width": 1200, "height": 830 },
  "groups": [{ "id": "voice", "label": "Голос" }, { "id": "write", "label": "автор" }],
  "captions": [{ "x": 570, "y": 118, "text": "регистры площадок" }],
  "coveredDirs": [".claude/skills/write-as-author"],
  "upstream": { "label": "/path/to/upstream", "prefixes": ["voice/", ".claude/skills/"] },
  "nodes": [
    {
      "id": "canon", "type": "canon", "group": "voice",
      "label": "i_am_just_a_text_file", "path": "voice/i_am_just_a_text_file.md",
      "summary": "Первоисточник голоса.",
      "layout": { "x": 600, "y": 330 }
    }
  ],
  "edges": [{ "from": "voice-core", "to": "canon", "kind": "derives", "label": "выжимка из" }]
}
```

Обязательны только `nodes` (у узла — `id` и `path` относительно корня) и `edges`;
всё остальное необязательно, манифест первой версии читается как есть.

- **`groups`** — порядок и подписи групп: так подписаны списки под графом и
  автоколонки. Группа, которая встретилась только у узлов, добавляется в конец
  с подписью, равной `id`.
- **`layout`** у узла — координаты центра блока на холсте. **Узлы без `layout`
  студия раскладывает сама:** по группам в колонки в порядке `groups`, ниже самого
  нижнего ручного узла (или с верха холста, если ручных нет), с подписью группы над
  каждой колонкой. Холст растёт по высоте, если узлы не влезли. Стартовый манифест
  из `npm run init` — целиком в авто-раскладке; ручные координаты нужны, когда хочется
  зафиксировать композицию.
- **`captions`** — свободные подписи на холсте для ручной композиции; **`canvas`** —
  размер холста, по умолчанию 1200×830.
- **`coveredDirs`** — папки, содержимое которых карта обязана описывать целиком:
  файл `.md`/`.py`/`.yaml` появился в такой папке, но узла с этим путём нет —
  студия покажет расхождение. Обычно это папки скиллов.
- **`upstream`** — другая копия тех же файлов (например, репозиторий методологии),
  с которой правка здесь разошлась бы. `prefixes` — префиксы путей узлов, у которых
  там есть близнец; перед сохранением такого файла студия предупредит, подставив
  `label`. Без `upstream` предупреждения нет.

Типы узлов (`type`): `canon`, `skill`, `reference`, `register`, `corpus`, `script`,
`doc`, `manifest` — от типа зависит только оформление блока. Виды рёбер (`kind`)
и их подписи в легенде: `always`, `platform`, `conditional`, `verify`, `subagent`,
`handoff`, `derives`, `precedence`, `step`, `deep`; незнакомый вид рисуется как
`conditional`.

Из редактора не правятся `corpus`-узлы и файлы `content/studio.json` и
`content/skill-map.json`, даже если их положить на карту: конфиг не должен
расширять права редактора, который он ограничивает.

## Отчёты

Разборы с цифрами: аналитика площадок, поведение постов, выводы по чужому опыту.
Появляются на `/reports` сразу после того, как файл лёг в папку —
пересобирать приложение не нужно.

`data.json` рядом с отчётом описывает графики: `{"blocks": [...]}`. Форм четыре,
и каждая отвечает за свою работу данных:

| `type` | Что показывает | Поля |
|---|---|---|
| `kpi` | плитки с числами | `items: [{label, value, note?}]`, `title?` |
| `bars` | сравнение величин по категориям | `title`, `items: [{label, value, note?}]`, `unit?`, `hint?`, `sample?` |
| `dumbbell` | две группы по одним и тем же признакам | `title`, `legend: {a, b}`, `items: [{label, a, b}]`, `unit?`, `hint?`, `sample?` |
| `stack` | доли целого, не больше шести сегментов | `title`, `items: [{label, value}]`, `hint?`, `sample?` |

В тексте отчёта блок ставится маркером `[[block:N]]` на отдельной строке, где `N` —
индекс в массиве `blocks` с нуля: цифра стоит рядом с абзацем, который её объясняет.
Блоки без маркера показываются в конце. Поле `sample` (размер выборки) заполнять
всегда: без него любая разница на картинке выглядит убедительнее, чем она есть.

Тот же формат — у дневных сводок Telegram и находок по проектам, только лежат они
в `.data/`, вне git.

## Кандидаты из звонков

`plan/candidates/<слаг>.md` кладёт внешний майнер: берёт расшифровки встреч,
оставляет только реплики автора и ищет в них мысли для поста. Студия меняет
в файле только `status` и `idea`.

```yaml
---
title: "Почему агенты ломаются на длинных задачах"
date: "2026-09-01"        # дата звонка
found: "2026-09-02"       # когда попало сюда
platform: telegram        # необязательно: куда просится
status: pending           # pending | accepted | rejected
idea: ""                  # id папки в ideas/, ставится при принятии
---
Прямая речь автора — то, что станет исходником идеи.
```

## Тренды

`trends/<дата>-<слаг>.md` кладёт внешний сборщик, обходя фиды из `trends/sources.md`.
Студия меняет только `status` и `idea`; текст карточки не трогает.

```yaml
---
source: hn                # id фида из sources.md
kind: discussion          # video | article | discussion
title: "Заголовок новости"
url: "https://…"
published: "2026-09-03"   # когда вышло у источника
found: "2026-09-04"       # когда попало сюда
status: new               # new | used | skipped
---
Суть за три строки, потом два-три угла, под которыми автор мог бы высказаться.
```

## Статусы идеи

`idea → draft → review → ready → scheduled → published`, плюс `parked` и `rejected`
в стороне от основного пути.

## Что важно знать

**Исходник не редактируется.** `source.md` остаётся таким, каким его надиктовали:
скиллы ставят материалы автора выше собственного синтеза, и подчищенный исходник
ломает эту иерархию.

**Публикует человек.** Студия сохраняет финальный текст и ссылку, но никуда ничего
не отправляет — см. границу №2 в [`../CLAUDE.md`](../CLAUDE.md) и `posts/README.md`.

**Память пополняется только с подтверждения.** Система может предложить правило,
но записать его в `rules.md` без нажатия кнопки не может.

## Приватность

Идеи и рамблинги — личные тексты. Они коммитятся в этот репозиторий, поэтому всё,
что не должно попасть в git, туда попадать не должно и в студию: для таких вещей
есть `.data/`, которая в git не уходит.
