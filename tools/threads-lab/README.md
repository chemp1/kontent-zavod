# tools/threads-lab — база постов Threads и разбор виральности

Собирает публичные посты Threads с метриками, чтобы понимать, что там заходит,
и проверять гипотезы о своих постах цифрами, а не ощущениями. Свои черновики
прогоняются через ту же разметку признаков (`score_own.py --drafts <папка>`).

## Главное ограничение, из которого следует всё остальное

**Просмотры отдельного поста Threads показывает только его автору.** По чужому
посту видны лайки, ответы, репосты и цитаты, и больше ничего. Поэтому:

- «виральность» здесь — это **превышение автором собственной нормы**:
  вовлечение поста, делённое на медиану этого автора. Сто лайков у аккаунта на
  тысячу подписчиков и у аккаунта на миллион — разные события, абсолютные числа
  между аккаунтами несравнимы;
- доля ответов в вовлечении считается отдельно: в Threads охват растёт с
  диалога, так что это ближайший доступный прокси охвата;
- свои посты — отдельная история: по ним Threads отдаёт полную статистику
  во вкладке «Статистика», включая просмотры.

## Как запускать

```bash
python3 collect.py --account <handle> --scrolls 5    # лента одного автора
python3 collect.py --search "вайб-кодинг" --scrolls 8 # выдача поиска
python3 collect.py --watchlist --scrolls 5           # все из data/accounts.json
python3 candidates.py                                # кого нашла разведка
python3 analyze.py                                   # сводка по корпусу
python3 score_own.py --drafts /path/to/drafts        # свои черновики против профиля удачных
python3 report.py <ГГГГ-ММ-ДД-слаг>                  # числа для отчёта в студию
```

Зависимостей нет, venv не нужен: только стандартная библиотека.

## Как это работает

`collect.py` ходит в Threads не напрямую, а через браузер: по ssh на отдельную
машину, где стоит **залогиненный Chrome с CLI `browser`**. Хост задаётся
переменной окружения `BROWSER_SSH_HOST` (по умолчанию алиас `browser-host`
из `~/.ssh/config`). Headless-браузер тут не годится — Meta его не пускает.

Отсюда правила, которые нельзя нарушать:

1. **Только чтение.** Скрипт умеет ровно два действия: перейти по адресу и
   прокрутить. Никаких кликов, лайков, подписок и публикаций.
2. **Человеческий темп.** Паузы 3–8 секунд, один прогон в день. Ровный интервал
   и высокая частота — первое, на что смотрят анти-бот эвристики.
3. **Личный аккаунт автора для сбора не используется.** В браузере залогинен
   отдельный аккаунт: бан личного невосстановим.
4. **Своё окно закрывается за собой** (`window create` / `window close`):
   за той машиной может сидеть живой человек, и наши вкладки видит он.

Если сбор станет ежедневным и объёмным, его надо переносить с чужого браузера
на платный скрейпинг-сервис с бюджетным лимитом.

## Данные

`data/posts.jsonl` — одна строка на снапшот поста. Повторный сбор того же поста
в другой день **дописывается, а не заменяет**: так видно, как росли метрики.
Дублем считается пара (id, дата сбора).

| Поле | Что |
|---|---|
| `id`, `author`, `url` | опознание поста |
| `source` | `profile` или `search`. **Важно:** медиану автора считаем только по `profile` — выдача поиска смещена в сторону удачных постов |
| `published_at`, `collected_at`, `age_hours` | возраст на момент снятия метрик |
| `text`, `length` | текст без служебных строк интерфейса |
| `likes`, `replies`, `reposts`, `quotes` | метрики |
| `media` | `none` / `photo` / `carousel` / `video` |

`data/accounts.json` — вотчлист: кого собираем регулярно и зачем.

В анализ идут посты **старше 72 часов**: метрики растут первые сутки-двое, и
если смешать свежие со старыми, свежие систематически выглядят провальными.

## Чего эта база не делает

Не предсказывает виральность моделью. На корпусе в несколько сотен постов любая
модель переобучится и выдаст уверенные, но случайные правила. Пока это
описательная аналитика: чем верхний дециль отличается от остальных, с указанием
размера выборки рядом с каждым выводом. Разговор про предсказание имеет смысл
после нескольких тысяч постов и накопленной своей статистики.

## Если сломалось

- `Extension is not connected` — MV3-воркер расширения уснул. Повторить через
  пару секунд.
- Пустая выдача при живом соединении — вкладка уехала в `about:blank` либо
  Threads не успел отрисоваться. Увеличить паузу после `goto`.
- Метрики пустые у всех постов — Threads сменил подписи кнопок. Правится в
  `extract.js`: список `LABELS` и порядок кнопок (лайк, ответ, репост, цитата).
  Проверить подписи можно так:
  `ssh "$BROWSER_SSH_HOST" 'browser --session tlab eval "[...document.querySelectorAll(\"svg[aria-label]\")].map(s=>s.getAttribute(\"aria-label\"))"'`
- Числа профиля выглядят обрезанными (431 вместо 5 724 432) — Threads разделяет
  разряды узкими неразрывными пробелами; разбирать строку целиком, а не
  регуляркой по всей странице.

## Отчёты

Разборы по этим данным публикуются в студию, раздел «Отчёты»:
`content/reports/<ГГГГ-ММ-ДД-слаг>.md` в корне репозитория плюс необязательный
`<слаг>.data.json` с числами для графиков (его пишет `report.py`). Появляются
в студии на `/reports` без пересборки.
