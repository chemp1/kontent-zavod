# tools/voice-mine - идеи из собственных звонков

Берёт расшифровки встреч, **вырезает только реплики автора** и ищет в них мысли,
из которых может вырасти пост. Кандидаты ложатся в `content/plan/candidates/`
и ждут решения в студии, раздел `/plan/candidates`.

Ни в какую базу и ни к какому нотетейкеру скрипт не ходит: на входе у него
JSONL-файл, а откуда он берётся - забота обвязки, которая в репо не входит.

## Вход

`.data/tools/voice-mine/transcripts.jsonl` (другой путь - `--from-jsonl`). Одна строка -
один звонок:

```json
{"transcript_id": "abc123", "day": "2026-08-27", "title": "Созвон по продукту",
 "sentences": [{"speaker": "Имя Фамилия", "text": "..."}, {"speaker": "Другой Участник", "text": "..."}]}
```

- `speaker` сверяется с именем автора **точно**, как оно подписано в расшифровке.
  По умолчанию берётся `name` из `voice/author.json`, иначе `--me "Имя Фамилия"`.
- `transcript_id` нужен для памяти о разобранном (`.data/tools/voice-mine/state.json`);
  без него берётся хэш даты и названия.
- Если у реплик есть `index`, порядок восстанавливается по нему числом.

Файл кладёт любая команда, записанная в `DUMP_COMMAND` (см. `.env.example`):
`run.sh` запускает её перед разбором. В файле лежат все реплики, включая чужие -
поэтому он живёт в `.data/` и в git не попадает.

## Приватность - это устройство, а не обещание

Из звонка наружу выходит только прямая речь автора. На это работают три слоя:

1. **`extract_speech()`** берёт реплики только с `speaker == автор`. Чужие
   реплики дальше `.data/` не уходят, из них считается лишь список имён для слоя 3.
2. **Промпт** запрещает упоминать собеседников, их компании и подробности их дел.
3. **`redact()`** выкидывает цитату, в которой всё-таки всплыло имя участника
   того звонка. Запрет в промпте - не механизм; здесь механизм.

Сырьё (речь автора по звонкам) и память о разобранном лежат в `.data/tools/voice-mine/`.

## Запуск

```bash
python3 tools/voice-mine/check.py --days 7 --dry-run     # какие звонки и сколько речи автора
python3 tools/voice-mine/check.py --days 7 --limit 1 --no-notify
python3 tools/voice-mine/check.py --days 7               # обычный прогон
python3 tools/voice-mine/check.py --from-jsonl /path/to/calls.jsonl --me "Имя Фамилия"
```

`--dry-run` ничего не пишет и агента не зовёт: печатает список звонков и объём
речи автора по каждому. Настройки прогона (уведомление, ссылка на студию,
команда дампа) - в `tools/voice-mine/.env`, образец в `.env.example`.

**В крон ставится осознанно.** Скрипт видит все встречи, где говорил автор, а среди
них бывают продажи и разговоры один на один. Сначала решение, какие звонки вообще
можно брать, потом строка в crontab с `run.sh`.

## Грабли

**Категория встречи из нотетейкера не помогает.** Свои созвоны он размечает хуже
чужих: у собственных звонков категория чаще всего пустая, и фильтровать приходится
не типом встречи, а решением человека.

**Порядок реплик сортировать числом.** Индекс реплики приходит строкой, и при
сортировке строк «10» встаёт между «1» и «2».

**Голосовые команды боту - не источник идей.** Диктовка ответов конкретным людям -
это оперативка, а не размышление вслух; такие сессии в разбор не берём.
